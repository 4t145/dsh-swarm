## Lead 独立核验

两次均实际检查：

1. 原 checkout 仍在 main，HEAD 等于初始基线，status 干净，tracked 文件及 index 与 HEAD 无差异。创建 worktree 所需的共享 Git 对象/refs 不是“整个仓库零写入”。
2. 实际 result ref 等于记录 acceptedHead，集成 worktree HEAD 也等于该 SHA。
3. 相对基线，第一份结果仅修改加法/乘法实现，第二份仅修改 double 实现；测试与包清单的 diff 均为空。
4. 在确认 HEAD 的集成 worktree 再运行 `node test.js`，两次均输出 `ok`、退出 0。
5. `swarm_manage status` 显示 completed、admission closed、两个 worker inactive；成功依据是持久终态和匹配验证，不是 inactive 本身。

## 发现与修复

- 实跑中，code task 进入 done 后，worker.currentTaskId 仍指向它，造成状态/进度面板误报当前任务。[集成模块](<../src/integration.ts>) 现在在同一次 acceptance 更新中清除匹配指针，保留 Task.ownerWorkerId 作为历史归属；恢复补记同样复用此路径。
- [回归测试](<../tests/integration.test.ts>) 覆盖普通接受清指针、失败仍保留 claimed 指针、Git 已发布但 domain 写失败后的恢复补记，以及不清除不同任务指针。
- [worker 协作指令](<../src/worker-policy.ts>) 明确验证的是“当前 acceptedHead 合并本次提交”的组合树，不会批量合并尚未接受的 peer proposal；应协调可独立验证的增量或依赖完整的提交。没有改动架构 §8.2 的串行验证规则。
- 最后执行 `pnpm typecheck`、`pnpm test`（23 文件 / 268 项）、`pnpm build` 均通过；另外直接执行 [原生 headless 脚本](<../scripts/test-native-headless.mjs>)，缺失路由提前失败和两个原生 worker 的 SIGINT→持久 stopped→退出 130 均通过。后者使用明确的阻塞测试 adapter，不是第三次真实模型编码验收。
